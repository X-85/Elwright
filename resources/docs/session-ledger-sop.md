# 会话问题台账 · 离线 SOP

> 这是内置技能 `session-ledger` 的离线降级文档。配置 LLM 时，Elwright 会根据你的输入生成适合交给代码 Agent 的台账指令；离线时按本文手动启用。

## 用途与边界

会话台账用于追踪长会话中的问题、方案、验证结果、决定和下一步。它应该由能读写当前工作区的 Agent 维护。Elwright 当前不会自动创建或修改项目文件。

## 初始化

在项目根目录建立：

```text
session/
├── index.md
├── events.md
├── decisions.md
└── archive/
```

`index.md`：

```markdown
# 会话问题索引

| 编号 | 问题 | 状态 | 最近进展 | 下一步 |
| --- | --- | --- | --- | --- |
```

`events.md`：

```markdown
# 会话事件
```

`decisions.md`：

```markdown
# 会话决定
```

## 每轮维护

1. 先读 `session/index.md`，判断本轮归属的 `Q1`、`Q2` 等问题。只有目标、原因或交付物明显不同才建立新编号。
2. 仅读取 `events.md` 中当前问题的记录；只有历史回溯时才搜索 `session/archive/`。不要每轮加载全部事件、决定或归档。
3. 完成正常工作后，在 `events.md` 追加：

   ```markdown
   ### Q编号 | 第N次处理
   - 问题或新增信息：
   - 本轮方案：
   - 实际结果：
   - 下一步：
   ```

4. 更新 `index.md` 对应行。状态只能使用：待处理、处理中、已解决、阻塞、搁置。
5. 长期有效且已确认的结论写入 `decisions.md`。明确区分已验证、未验证、失败和推测，不能把计划写成结果。

## 归档与答复

每 5 至 10 轮轻量整理一次。已解决且近期不再讨论的问题，将其完整事件移动到 `archive/events-YYYY-MM.md`，在 `index.md` 保留简短结果；这不是删除历史。

完成每轮后附带：

```text
[台账更新]
问题：Q编号，或“新建 Q编号”
本轮：一句话总结
状态：当前状态
下一步：一句话总结
```

没有新增进展时写 `[台账更新]\n无新增问题进展`。
