# plan：窗口布局按钮对齐 macOS 原生行为

日期：2026-08-31 · 类型：enhancement · 来源：用户反馈 Q23-2
「最大化的按钮能否参考 mac 上常见软件实现方式，比如移动以及调整大小」

## 现状 vs 原生

| 原生 macOS 绿点 | Elwright 改前 |
| --- | --- |
| 点击 = 进入/退出全屏 | 点击无动作（仅悬停菜单） |
| 悬停 = 「移动与调整大小」菜单 | 悬停菜单已有（自创分区：左半屏/右半屏/…/三列/四格） |
| 菜单含四角四分之一填充 | 只有单一「四格排列」= 左上角（其余三角无入口） |
| 退出全屏自动恢复原尺寸 | 同原生（系统行为）✓ |

## checklist

- [x] 绿点点击 → `toggleFullscreen()`（isFullscreen 切换；不动 savedWindowBounds，退出由系统恢复）
- [x] `applyWindowLayout` 新增 `quarter-tl/tr/bl/br` 四角布局，移除 `four-grid`（其=左上角，被四角取代）
- [x] 菜单文案对齐原生措辞：移动与调整大小（移到屏幕左侧/右侧/上半部/下半部）+
      填充与排列（左上/右上/左下/右下/填充屏幕/三列排列）+ 全屏（可切换）+ 恢复窗口
- [x] `Grid2X2` 图标随四格排列移除；四角用文字按钮（无贴合图标，文字更直观）
- [x] CSS：`.window-layout-quarter` 字号 11px
- [x] lint + vitest + build 全绿；真机验证全屏进出与窗口恢复

## 拒绝 / 后置

- 双击标题栏缩放（原生另一惯例）：与拖拽手势 `startWindowDrag` 叠加需处理双击判定，独立小任务再做。
- Option+点击缩放（zoom 填充工作区不进全屏）：与「填充屏幕」按钮语义重复，不重复做。
- 触发方式维持 hover（原生同为 hover）；不改 click 展开。
