# ADR-001 — 脑图 MVP（大纲式树形思维导图）

- **状态**：已接受（2026-09-01，用户定向「立项脑图 MVP 或工程图 MVP 作为下一个主干重心，ADR 写好后直接开发」；本 ADR 选定脑图先行，理由见 §弃选）
- **Feature**：mindmap（本目录为新功能文档根）
- **路线图**：`docs/ROADMAP.md` §后置验证「脑图 MVP」——主干闭环稳定后验证的解锁项；准入：本地脑图、节点编辑、与 Todo/能力的关联；**不做** AI 草稿、复杂知识整理、桌宠入口、多人协作、云同步、通用白板

## 背景

工作台已有 Todo/今日记录、资源与课题工作区、AI 对话、代码浏览器。知识整理场景
（读书笔记、会议纪要、部署思路拆解）缺少一个轻量的层级组织工具。路线图把
「本地脑图 + 节点编辑 + 与 Todo/能力的关联」定为 MVP 边界。

## 决定

### D1 — 先做脑图，工程图 MVP 顺延

- 脑图是大纲树：数据结构（父子树）与交互（增删改/折叠/缩进）都比自由画布流程图
  （节点拖拽 + 连线 + 正交布线）小一个量级，可一次交付可用闭环。
- 工程图 MVP 依赖 Mermaid 渲染（~1MB 级前端依赖）与画布编辑器，适合独立一批。
  脑图先行不阻塞工程图——两者数据模型独立，无返工风险。

### D2 — 大纲式树形编辑，不做自由画布

- 形态：**左侧根 + 纵向层级缩进的大纲树**（类 Workflowy/幕布），非放射状画布。
  折叠/展开、兄弟排序（上移/下移）、缩进（Tab/Shift+Tab）、回车加兄弟节点。
- 弃选放射状画布：需要节点自由拖拽 + 贝塞尔连线 + 碰撞布局，MVP 复杂度失控；
  大纲式已覆盖「层级组织知识」的核心价值，且天然适配键盘流。
- 节点数据：扁平 `Vec<Node>` + `parent` 指针（非嵌套 JSON），增删/移动 O(1) 改指针，
  序列化稳定不抖动。

### D3 — 存储走 Rust core（`~/.elwright/mindmaps/`），不走 localStorage

- 一图一文件 `<id>.json`（与 chats 一文件一会话同模式）；原子写（tmp+rename）。
- 理由：与 Todo/今日记录/工作台存储同层（`core::` + IPC），CLI 未来可读；
  损坏单图不拖累其他图；localStorage 有配额与清理风险。
- IPC：`mindmap_list / mindmap_create / mindmap_save / mindmap_delete`（MVP 四个，
  全量保存不搞增量）。

### D4 — 与 Todo/能力的关联（MVP 最小实现）

- 节点 → Todo：节点行内「转 Todo」按钮，复用现有 `todo_add`，节点标注已转标记。
- Todo → 节点：脑图侧栏「从 Todo 导入」，把未完成 Todo 挂到选中节点下（可重复触发）。
- 能力关联（节点直接调用能力）留后续——MVP 只做与工作台 Todo 的双向搬运。

### D5 — LLM 是增强不是地基

- MVP 零 LLM 依赖：离线全功能。AI 草稿（一句话生成子树）等按路线图后置，
  届时以独立 ADR 评估。

## 与既有规划文档的关系

实施时发现 `docs/features/mindmap/` 存在 2026-08-22 的规划文档（README MVP 清单、
嵌套 JSON schema 草案、愿景 behavior）。本 ADR 对其做一次**收窄**：
撤销/重做、颜色/标签/备注、缩放平移、导出、书签/能力/AI 多对象关联均未纳入 MVP，
已显式转入 README「当前状态」与 behavior「后续升级」；数据模型由嵌套树改为扁平 DFS
（architecture 已注记）。关联设计的 `{type,id}` 引用式方案保留给后续多对象关联。

## 后果

- 新增 `core::mindmap` + 4 IPC + Bridge 4 方法 + `MindmapView.vue` + 侧栏入口。
- 测试：core 单测（树操作/持久化/损坏容忍）+ IPC 冒烟 + 前端键集守卫 + e2e 冒烟。
- 工程图 MVP 顺延为独立批次（Mermaid 引入需评估 bundle 体积）。
