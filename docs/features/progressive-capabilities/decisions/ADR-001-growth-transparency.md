# ADR-001：成长体系透明化——解锁规则可视 + 成长提示

日期：2026-08-31 · 状态：已接受（实施随 enhancement-2026-08-capability-growth）
关联：渐进式发布 MVP（PR #1）后续；ROADMAP「能力渐进式发布——后续增加透明的解锁规则、成长提示」

## 背景

MVP 已有机制：`releaseTier` 档位 + `unlockAfterUses` 本地累计使用门槛 + 「查看全部能力」
开关，但 1) 锁定原因与条件不可见（「达到本地解锁条件」不说是啥条件、不报进度）；
2) 无成长反馈（跨过阈值没有任何提示）；3) 内置注册表 4 条全部核心档位，成长链路
对用户完全不可见。

## 决策

1. **规则透明（三处同文案）**：列表「待解锁」徽标 tooltip / 详情页锁定横幅 /
   侧栏成长提示行，统一展示「累计使用任意能力 N 次后自动解锁（当前 T/N）」；
   `unlockAfterUses` 缺失的 tier>1 能力显示「暂未开放解锁条件」。
2. **成长提示（两个时机）**：
   - 跨阈值瞬间：全局 toast「🎉 已解锁进阶能力「名称」」（复用既有 notify 通道）；
   - 持续进度：侧栏提示行显示距最近可解锁项的差距「距解锁「Y」还差 N 次（累计 T 次）」。
3. **示例策略**：内置 `weekly-report` 升为 `releaseTier: 2` + `unlockAfterUses: 3`
   （技能型示例是最自然的「进阶」样本），让新用户开箱即体验完整成长闭环；
   MVP 行为文档「内置示例全部核心档位」随之更新。⚠️ 该示例默认从列表隐藏、
   累计使用 3 次后解锁——改变既有示例的默认可见性，属本 ADR 需用户知悉的决策。
4. 逻辑收口在纯函数模块 `lib/growth.ts`（isUnlocked / growthSummary /
   newlyUnlocked），vitest 覆盖；App.vue 与两个组件只做展示接线。

## 拒绝 / 后置

- **按能力单独计数**：MVP 语义即「累计任意能力使用次数」，改单能力计数破坏既有
  本地数据且解释成本高；维持总量语义。
- **解锁条件远程下发 / 社区签名能力包**：ROADMAP 已注明另行排期，不进本 ADR。
- **localStorage 数据迁移**：字段与键名不变，无迁移。
- **桌面通知/系统级提醒**：应用内 toast 足够，不引通知权限。
